## 7. 모션 규범 (다음 화면의 일관성 기준)

emil `animate` 게이트를 통과한 확정값. **새 화면도 이 표를 따른다.**

| 상황 | 값 |
|---|---|
| 진입(접힘선 **위**) | `fade-in-up 400ms cubic-bezier(0.23,1,0.32,1)`, stagger 80ms |
| 진입(접힘선 **아래**) | `Reveal` 컴포넌트로 **스크롤 시점 발화**, `300ms` 동일 커브, stagger 50ms |
| 누름 피드백 | `active:scale-[0.98]`, 100–160ms |
| 호버 | 색 전환 150ms. Tailwind v4는 `hover:`를 자동으로 `@media (hover:hover)` 처리 |
| 표준 ease-out | `cubic-bezier(0.23, 1, 0.32, 1)` |

**규칙**
- 접힘선 아래 요소에 **로드 시점 애니메이션을 걸지 않는다.** 사용자가 스크롤해 오기 전에 재생이 끝나 아무도 못 본다. `components/common/Reveal.tsx`를 쓴다.
- UI 모션은 300ms 이하. 마케팅 표면만 더 길어도 된다.
- `ease-in` 금지. `cubic-bezier(0.4,0,0.2,1)`(Tailwind 기본) 금지.
- `transform`·`opacity`만 애니메이션한다.
- reduced-motion은 **상태가 아니라 CSS(`motion-safe:`)로** 처리한다. 그래야 숨김도 애니메이션도 함께 꺼진다.
- 순수 CSS 클래스(`.animate-fade-in-up` 등)에는 Tailwind 변형(`motion-safe:`)이 **안 먹는다.** arbitrary-property 문법을 쓸 것.

| 하드코딩 hex 7곳 | **오탐** — `bg-white/92` 칩 위 텍스트·반전 토스트·카카오 브랜드색은 테마 고정 표면이라 정당. audit.sh를 HIT→"확인" 등급으로 조정 |

**모션 규범 갱신 (§7 대체)**

| 대상 | 값 |
|---|---|
| 텍스트 진입(접힘선 위) | `fade-in-up 400ms cubic-bezier(0.23,1,0.32,1)`, stagger 80ms |
| **이미지 진입** | `shg-fade-in 500ms` 동일 커브 — translateY 4px + 페이드 (텍스트 16px보다 훨씬 작게 "안착") |
| 스크롤 진입(접힘선 아래) | `Reveal` 컴포넌트, `fade-in-up 300ms`, stagger 50ms |
| 누름 | `active:scale-[0.98]` 100~160ms |

**규칙**: 같은 효과를 전부에 복사하지 않는다. 각 모션은 무엇을 전달하는지 한 문장으로 말할 수 있어야 한다.
`transition-all` 금지 — 변하는 속성을 명시한다.

**시도했다 되돌린 것 (2번째)**: 이미지 전용 `shg-settle` 키프레임(`scale(1.02)→1`)을 globals.css에 추가했으나
dev 서버가 반영을 못 해 **콜라주가 통째로 안 보이는 회귀**가 났다(`opacity-0`만 남고 애니메이션 없음).
이미 컴파일된 `shg-fade-in`(4px)으로 대체. **교훈: globals.css에 새 키프레임·변수를 추가하는 변경은 이 프로젝트의 dev 서버에서 신뢰할 수 없다.**
새 CSS를 추가하는 대신 기존 키프레임·토큰의 조합으로 해결할 수 있는지 먼저 본다. 추가가 불가피하면 렌더로 반드시 확인한다.

# 제품 전체 리디자인 (2026-09-10, skill v4 첫 제품 단위 실행)

## 진단 (화면을 보고 나온 것)

1. **제품이 한 벌로 안 읽힘** — 랜딩(어둡고 사진 큼) / 대시보드(밝고 사진 카드) / 마법사·상세(무채색)가 서로 다른 사이트 같았다
2. **상세가 색 덩어리** — 커버(354×143)와 스텝 썸네일 4개가 전부 그라데이션 블록. 정보 0인 채로 화면의 30%를 점유

## 원칙 (다음 화면에도 적용)

- **사진은 보조다.** 있으면 강화하고, 없어도 구멍이 남지 않아야 한다. 폴백으로 큰 색 블록을 채우지 않는다

## 화면 간 시각 언어 통일 (2026-09-10)

"화면마다 다른 사람이 만든 것 같다"의 실체는 **형태 스케일이 흩어진 것**이었다. 레이아웃 구조는 각 화면의 역할에 맞아 건드리지 않고,
모든 화면이 공유하는 **radius·padding 스케일만** 통일했다.

**radius: 12종 → 4종**

| 역할 | 값 | 통합 전 |
|---|---|---|
| 카드·프레임 | `rounded-2xl` (16px) | `2xl`, `[18px]`, `[22px]` |
| 버튼·입력 | `rounded-xl` (12px) | `xl`, `lg`, `[13px]`, `[14px]` |
| 칩·점 | `rounded-full` | (동일) |
| 아이콘 사각 | `rounded-[10px]` | `[9px]`, `[10px]`, `[11px]`, `md` |

52곳 / 29개 파일 정규화. 핸드오프에 정의돼 있던 스케일(프레임24 / 카드16 / 입력·버튼12–14 / 칩999 / 아이콘10)이
지켜지지 않아 임의값이 섞여 있었다.

**카드 padding**: `p-4·p-5·p-6·p-7·p-[22px]` → 일반 카드 `p-5`(20px) / 여백 큰 카드 `p-6`(24px). 4의 배수 스케일.
StepCard `p-4→p-5`, 대시보드 카드 `p-[15px]→p-5`로 맞춰 타임라인과 카드 그리드가 같은 리듬을 갖는다.

**의도적으로 안 한 것**: 레이아웃 구조 통일. 랜딩(설득 → 사진 큰 비대칭) / 대시보드(스캔 → 격자) / 마법사(입력 집중 → 여백)는
각자 역할이 달라서 억지로 맞추면 오히려 나빠진다. 형태 언어만 공유하고 구성은 역할에 맡긴다.

**남은 임의 spacing**: `gap-[7px]`, `py-[15px]` 등 버튼 내부 미세조정 값들. 시각 언어에 미치는 영향이 작아 보류.

## 마법사 화면 수정 (2026-09-10, 사용자 지적)

radius·padding만 통일하고 **화면 자체를 보지 않아** 놓친 것들. §8-2 "스크린샷을 말로 묘사"를 이 화면에서 건너뛴 결과다.

빈 상태를 "값 자리에 `—`"로 채우지 않는다 — 보여줄 게 없으면 다른 것을 보여주거나 접는다.

## 색 위계 재설계 (2026-09-10, "전체적으로 색감은 괜찮냐?")

### 진단 — 색상환 census (제품 화면 실측, s>=20인 렌더 색만 집계)
상세 화면 라이트 기준, 재설계 **전**:

| 색상 | 값 | 빈도 | 정체 |

## 브랜드 표면 정리 (2026-09-21) — "탭 아이콘 색깔이 왜저래"

### 파비콘이 앱 어디에도 없는 조합이었다
직전에 내가 넣은 값이 **잉크 바탕 + 샤르트뢰즈 마크**였는데, 앱의 로고는
라이트 = 잉크 + **흰** 마크 / 다크 = 샤르트뢰즈 + 잉크 마크다. 파비콘만 제3의 조합이었다.
파비콘은 테마를 따라갈 수 없으므로 **기본 테마(라이트)의 로고**에 맞춘다. 대비도 10.95 → 17:1.

### 더 큰 문제 — 마크가 작은 크기에서 뭉갠다 (실측)
`rsvg-convert`로 실제 래스터해서 확인했다.

| 크기 | 상세형 마크 | 판정 |
|---|---|---|
| 16px | 내부 획이 전부 합쳐져 흰 얼룩 | **읽히지 않음** |
| 32px(레티나 탭) | 지구 + 대륙으로 읽힘 | 통과 |

**이건 파비콘만의 문제가 아니었다.** `Logo`는 사각형의 62%를 마크로 쓰므로
사이드바(28 → 17px)·헤더(26 → 16px)가 정확히 그 구간이다. 같은 얼룩이 앱 안에도 있었다.

→ **크기별 두 마크**(표준적인 responsive logo 처리):
- 마크 실치수 **30px 미만** = 단순형(원 + 경선 하나, stroke 2.4). 사이드바·헤더·파비콘
- **30px 이상** = 상세형(경로가 지구를 가로지르는 원본). 로그인(38)·온보딩(35)·apple-icon·OG

후보 3종을 16px로 래스터해 비교했고(상세형 / 원+경선+적도 / 원+경선),
**원 + 경선 하나**만 형태가 남았다. 적도선을 더하면 내부가 다시 찬다.

### 공유 링크 — 앱 밖으로 나가는 유일한 표면인데 비어 있었다
`/shared/[token]`에 `generateMetadata`가 **아예 없었다.** 카카오톡·슬랙에 붙인 모든 공유 링크가
사이트 기본 제목으로 똑같이 떠서 어느 여행인지 분간이 안 됐다.
- 일정별 제목·기간 메타 추가. SSR이 이미 부르는 `fetchShared`를 재사용(Next가 dedupe)
- 제목은 LLM 생성물이라 화면과 같은 `normalizeText()`로 em-dash를 정규화
- 토큰이 URL에 노출되므로 `noindex, nofollow`. 미리보기만 살린다
- 검증: 만료 분기(실제 만료 토큰) + 성공 분기(만료일 임시 연장 후 원복) 둘 다 실물 확인

### 나머지 브랜드 표면
| 표면 | 전 | 후 |
|---|---|---|
| 링크 미리보기 이미지 | 없음 | `opengraph-image.tsx` (1200×630, 실물 렌더 확인) |

### 이전 보고가 틀렸다
"타이포 22종 → 7단계로 정규화(52곳)"라고 보고했는데, 그건 `text-[Npx]`만 센 것이었다.
**Tailwind 프리셋(xs 12 / sm 14 / base 16 / lg 18 / xl 20 / 2xl 24)이 96곳에 그대로 남아 있었다.**
실제 렌더 치수는 11·12·12.5·13·14·15·16·17·18·20·23·24·30·34·52 = **15종**이었다.

정리 후 **10종**: 11 · 12(xs) · 13 · 14(sm) · 15 · 17 · 23 · 30 + 히어로 34·52.
- `text-[12.5px]`(23곳) → `text-xs`(12px). 0.5px 차이는 의도적으로 쓸 수 없는 간격이라 한쪽을 없앴다
- `text-base`(16)·`text-lg`(18) → `text-[17px]`. **ErrorState 18 / EmptyState 16 — 형제 컴포넌트인데 달랐다**
- `text-2xl`(24)·`text-xl`(20) → `text-[23px]`. **로그인 24 / 온보딩 20 — 형제 화면인데 달랐다**
- 랜딩 워드마크 16 → 15 (사이드바·헤더 워드마크와 동일)

남은 건 `text-sm`(14px, 39곳)이 13과 15 사이에 있는 것. 이번 세션엔 인증 화면을 렌더할 수 없어
39곳을 눈으로 못 보므로 **손대지 않았다** — 검증 못 하는 일괄 변경은 하지 않는다.

### 상세 제목: 30px + truncate가 최악의 조합이었다
`text-[23px] sm:text-[30px] truncate` — 640px부터 2000px까지 **계속 30px**이었다.
LLM이 만드는 제목은 60자가 넘는 문장인데 배너 크기로 키운 뒤 잘라버렸다.

폭별로 실제 래스터해서 비교했다(헤드리스 chromium, 본문 칼럼 폭 실측 반영):

| 폭 | 30px + truncate (현재) | 23px + 2줄 clamp |
|---|---|---|
| 390 | 14자 | 33자 |
| 1024 | **17자** | 50자 |
| 1440 | 33자 | **제목 전체** |

→ `text-[23px]` 고정 + `line-clamp-2`. **30px는 어느 폭에서도 정보를 더 주지 못했다.**
제목은 배너가 아니라 식별자다. 17px도 재봤지만 15px 장소명과 위계가 무너져 기각.

같은 처리를 필요로 하던 곳:
- **대시보드 히어로 카드** — `h-[200px] overflow-hidden`인데 제목에 clamp가 없었다.
  긴 제목이 3줄이 되면 아래 태그 줄이 카드 밖으로 밀려 잘린다. `line-clamp-2` 추가
- 공유 페이지 제목도 `truncate` → `line-clamp-2`
- 마법사 heading은 반응형 단계가 **아예 없어** 390px에서도 30px였다 → `text-[23px] sm:text-[30px]`

### 영업시간 한 줄이 순수 소음이었다
Google 원문은 7요일을 전부 나열한다. 대부분 7일이 같은 값이라 같은 문장이 7번 반복되고
카드 폭을 넘겨 마지막 요일이 잘린 채 끝났다 — 한 줄을 다 쓰면서 정보는 0.

`lib/utils/openingHours.ts`: 같은 시간대의 **연속 요일**을 묶고 24시간제로 줄인다.
원문은 `title` 속성에 남긴다. 파싱 실패 시 원문 그대로(형식이 바뀌어도 화면이 비지 않게).

| 입력 | 출력 |
|---|---|
| 7일 동일 | `매일 11:00 - 21:00` |
| 금·토만 다름 | `월-목 11:30 - 01:00 · 금·토 11:30 - 02:00 · 일 11:30 - 01:00` |
| 일요일 휴무 | `월-토 09:00 - 18:00 · 일 휴무` |
| 24시간 | `매일 24시간 영업` |
| 형식 불일치 | 원문 그대로 |

## 로고 재설계 (2026-09-21) — "로고 안예쁜데"

지구+경선 마크는 **브라우저 기본 아이콘처럼** 생겨 브랜드가 없었다. 작게 만들려고 단순화했더니
오히려 어디서나 보는 stock 글로브가 된 것이다.

### 버린 방향
**S자 길**(두 원으로 만든 S 곡선) — 래스터해보니 그냥 **글자 S**로 읽혔다.
사용자가 이미 싫다고 한 "이니셜 네모"로 되돌아간 셈이라 기각.

### 정한 방향: 굽은 길 + 도착점
이 앱이 실제로 그리는 것은 **경유지를 잇는 경로**다. 그걸 마크로 삼았다.
곡선이 S를 그려 이름(SHG)과도 겹치고, 도착점 하나만 샤르트뢰즈라 브랜드색이 들어간다.

16·28·64px로 전부 래스터해 고른 형태다:
- 링(지도 마커) 변형 → 16px에서 구멍이 막혀 덩어리가 됨
- 획/도트 분리 변형 → 16px에서 점이 떠 보임
- 출발점 도트 추가 → 둥근 캡에 묻혀 보이지 않음
→ **획 하나 + 원 하나**(v1)가 모든 크기에서 유일하게 형태를 유지.

부수 효과: 16px에서 뭉개지지 않으니 **크기별 두 벌(상세/단순)을 유지할 필요가 없어졌다.**
`Logo`에서 분기 로직을 지웠다.

### 색은 테마를 따라가지 않는다
브랜드 마크는 어디서나 같아야 하고, 파비콘·apple-icon·OG는 리터럴이라 애초에 테마를 못 따라간다.
앱만 반전시키면 **탭과 사이드바가 다른 로고로 보인다** — 이번에 지적받은 것이 정확히 그거였다.
잉크 사각형 고정. 다크 캔버스(#0d0e12)와 잉크(#1c1c1e)는 대비 1.13이라 묻히므로
`ring-1 ring-white/10`로 가장자리만 분리했다(라이트에서는 사실상 안 보인다).

OG 이미지(1200×630)에서는 감싸는 사각형을 뺐다 — 잉크 사각형을 잉크 배경 위에 두면 묻힌다.
큰 캔버스에서는 마크만으로 충분하다.
